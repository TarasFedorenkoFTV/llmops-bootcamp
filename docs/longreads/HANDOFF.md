# Статус: лонг-ріди L01–L12 — ГОТОВО

Задача цього handoff-документа виконана повністю. Він лишається як журнал
рішень; для будь-якої нової роботи над лонг-рідами — [STYLE.md](STYLE.md).

## Що зроблено

- `L01.html` … `L12.html` — усі 12 лонг-рідів у єдиному стилі й глибині
  (обсяг кожного в межах ±15% від L01), навігація між уроками, [index.html](index.html).
- Розподіл core/optional по уроках (CB, PII-guardrail, semantic cache, canary,
  judge, /metrics — опційні) узгоджений між лонг-рідами, конспектами
  `docs/lessons/`, ДЗ `starter/homework/` і кодом еталонів.
- Сторінки — **база знань для студента**: жодних продакшн-нотаток
  (правило зафіксоване у STYLE.md). Нотатки для запису відео — у
  [PRODUCTION.md](PRODUCTION.md).
- Знеособлений практичний досвід вплетено в кожен урок (без назв продуктів,
  компаній і номерів задач).

## Виправлення джерел, зроблені по ходу (щоб не розійтися знову)

- Еталон `w3`: tool-відповіді не кешуються (`toolCall == null`) — як каже L05.
- Конспекти L07/L08: circuit breaker і PII-guardrail позначені опційними.
- Конспекти L03/L06/L12: fallback-політика і mock-резерв, чесний слід
  tool-виклику (колонки `tool` у `requests` немає — це перший крок аудиту
  студента), опційність half-open у фінальному сценарії.
- Шаблон `eval-gate.yml` синхронізований зі starter в усі бранчі solutions
  (wait-gateway, `if curl`-проби).

## Правила, які тримають узгодженість

1. Будь-який факт лаби має відтворюватися на відповідному бранчі `wN` —
   якщо ні, виправляй еталон, а не формулювання.
2. Зміна розподілу core/optional проходить одночасно по чотирьох місцях:
   конспект → лонг-рід → hwN → еталон.
3. Чек-лист перед зміною сторінки — у STYLE.md.
