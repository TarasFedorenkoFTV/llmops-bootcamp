# Демо-сценарій: стартер і фінал поруч

10 хвилин, щоб показати весь курс: що студент отримує на вході і що має на виході.

## Підготовка (один раз)

```sh
# термінал 1 — стартер (те, що студент клонує на L01)
cd llmops-bootcamp/starter
docker compose up --build

# термінал 2 — фінал (еталон w6, на зсунутих портах — працюють паралельно)
git clone -b w6 https://github.com/TarasFedorenkoFTV/llmops-bootcamp-solutions
cd llmops-bootcamp-solutions
docker compose -f docker-compose.yml -f demo-ports.yml up --build
```

Відкрити поруч: **стартер** http://127.0.0.1:4200 і **фінал** http://127.0.0.1:4300.

## Сценарій

1. **Точка А (стартер, :4200).** Чат уже відповідає (через LiteLLM у mock), але вся
   консоль — «—»: жоден ендпоінт control plane ще не реалізований. Це стан студента
   після першого уроку.

2. **Точка Б (фінал, :4300).** Напиши кілька повідомлень — плитки оживають самі
   (консоль автооновлюється):
   - «Як скинути пароль?» двічі → росте **Cache-hit**, у другої відповіді latency майже миттєво (<50 мс);
   - «Де моє замовлення #10482?» → у чаті чип `🔧 lookup_order` і результат;
   - «Хочу повернути гроші, це терміново» → тікет НЕ створюється — заявка з'являється
     в **Approvals**; натисни `approve` — виконано (HITL наживо);
   - `__fail_503` → ввічлива заглушка замість 500, **Fallback** +1, **Error rate** росте;
   - за кілька секунд звичайне питання знову працює (circuit breaker з half-open).

3. **Rollback з UI.** У картці Prompt registry натисни «зробити активною» на v1
   (поганий промпт) → бот починає відповідати «не знаю». Поверни v2 — усе працює.
   Саме цю регресію в курсі ловить eval-гейт у CI.

4. **Гейт у CI.** Показати PR #1 у репо стартера: в історії — червоні прогони
   (реальні знахідки під час підготовки) і зелений `eval: 6/6`.

## Що це доводить

- Розрив «точка А → точка Б» — це рівно 6 тижнів × 2 уроки × 1 шар control plane.
- Усе працює на mock: нуль витрат на демо і на навчання.
- Кожен елемент демо прив'язаний до уроку (плитки й картки підписані L02…L08).
